# clip-image-text-retrieval

[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
![Python](https://img.shields.io/badge/python-3.10%20%7C%203.11-blue.svg)

Image-text retrieval and embedding analysis with CLIP ViT-B/32 and ViT-L/14: cosine matrices, retrieval metrics in both directions, PCA and t-SNE views, failure analysis and a quantitative look at the modality gap.

## Problem

CLIP-style models embed images and text in one space and retrieve across modalities by cosine similarity. Two questions are easy to confuse:

1. Does retrieval work? (Is the right text ranked first for each image?)
2. Do matched image-text pairs sit *close together* in the embedding space?

This repo measures both on the same data and shows they can disagree.

## Approach

- **Data:** 7 images and 12 texts with hand-labelled valid matches (the astronaut has two), near-miss distractors (tea vs espresso, astronaut on the moon) and clear distractors (dog, airplane). Labels are fixed before evaluation in `data/labels.json`. Eight further hard distractors form an expanded run that is reported separately and never mixed into the core numbers.
- **Models:** `openai/clip-vit-base-patch32` and `openai/clip-vit-large-patch14`, each with its own processor. Same images, texts and labels for both.
- **Evaluation:** L2-normalised embeddings, cosine similarity for every pair, rankings in both directions, Top-1 and Mean Rank (queries with no valid match are excluded from metrics and counted, but kept in matrices and rankings), PCA and t-SNE of the joint embedding.
- **Determinism:** seed 42 everywhere, t-SNE perplexity 5 (19 points), stable tie-breaking in rankings.

## Key findings

**The modality gap is the main result.** Both models retrieve perfectly (Top-1 100%, Mean Rank 1.00, both directions), yet in the 2D projections the nearest text to an image is a valid match for only **2/7 (B/32) and 3/7 (L/14) images with PCA, and 1/7 and 1/7 with t-SNE**. Images and texts form two separate groups; the centroid distance between them is about 0.88 (B/32) and 0.91 (L/14) in the L2-normalised space. Retrieval needs only the *relative order* of scores within one query, so it survives a large constant offset between modalities. 2D distance between an image point and a text point does not.

- Absolute cosines are low. The mean cosine of valid pairs is about 0.32 (B/32) and 0.26 (L/14), against 0.15 and 0.09 for invalid pairs. Only the ranking is meaningful.
- No top-1 error occurred, even with 8 extra hard distractors (20 texts), so the failure analysis uses the closest near-misses: "a cup of tea on a wooden table" scores about 0.276 against 0.315 for the espresso text on the coffee image (B/32).
- On 7 images the two models tie on every retrieval metric, so no claim of superiority is possible.

## Quickstart

```bash
git clone <repo-url> && cd clip-image-text-retrieval

# pip
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
# or conda
# conda create -n cliptr python=3.11 -y && conda activate cliptr && pip install -r requirements.txt

python src/clip_eval.py                     # full run, both models -> results/
python src/clip_eval.py --models clip-vit-base-patch32   # one model only
python src/clip_eval.py --offline           # locally cached models only
python src/clip_eval.py --dry-run           # random embeddings, code-path check only
```

Colab: open `notebooks/run_all.ipynb` from GitHub (File > Open notebook > GitHub tab) and choose Runtime > Run all. CPU is enough; ViT-L/14 is noticeably slower than B/32.

```

```

## Limitations

- Seven images and twelve texts is a toy set. It cannot rank models, and small differences are noise.
- PCA and t-SNE distort distances. The modality-gap claim rests on cosine statistics as well as the plots.

## Scope

This repo implements the CLIP image-text retrieval task end to end, matching
the original brief. Earlier drafts explored additional models (SigLIP) and
benchmarks (CIFAR-10); those were removed to keep scope faithful to the brief.
